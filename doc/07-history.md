| 项 | 值 |

## AI 协作说明

这个项目的开发方式本身就是一份可复制的经验。

### 每个功能模块的固定流水线

```
brainstorming  想清楚要什么（意图、边界、验收）
     ↓
spec           design doc → docs/superpowers/specs/<date>-<module>-design.md
     ↓
plan           实施计划 → docs/superpowers/plans/<date>-<module>.md（拆 3-7 个 task）
     ↓
SDD            子代理驱动开发
               ├─ implementer 子代理：按 task 实现
               ├─ reviewer  子代理：独立审查
               └─ 逐 task 闭环 → 整体验证 → 推送
```

### 关键约定

- **设计先行**：没有 spec 不开工。接口、数据模型、错误码、边界都在 spec 里定死。
- **实现与审查分离**：implementer 和 reviewer 是不同的子代理，避免自我确认偏差。
- **文档即资产**：19 篇 spec + 20 篇 plan 全在 `docs/superpowers/`，是最完整的设计档案。
- **AGENTS.md 是主索引**：每个模块落地后回写对应小节，这是接手时最该先读的文件。
- **SDD 台账可丢弃**：`.superpowers/sdd/` 是开发过程产物（各模块的 task 台账），不影响运行，接手后可忽略或清理。

### 会话规模

本开发周期约 **1420 条消息，跨 21 天**（2026-08-21 → 2026-09-11）。密集产出集中在最后三周：交易闭环、双角色、消息中心、以及整个管理后台 + C 端补全。
