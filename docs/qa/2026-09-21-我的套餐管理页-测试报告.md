## 二、缺陷与观察项

### 🔴 D-1 弹窗按钮显示英文（真实缺陷，影响 2 条用例 F1/G1）

| 项 | 内容 |
|----|------|
| 现象 | `uni.showModal` 的按钮渲染为 `Cancel` / `OK`，而非「取消」/「确定」 |
| 证据 | F1 删除弹窗 innerText：`删除套餐\n确定删除「用例-固定价」吗？删除后不可恢复，历史订单不受影响\nCancel\nOK`；G1 预填弹窗同样 |
| 影响面 | **全局**：所有用 `uni.showModal` 的地方（删除套餐、退出登录、拉黑、报名等）都会显示英文按钮 |
| 根因初判 | uni-app H5 的模态按钮文案取自 locale，当前未设 `zh-Hans`，故回落英文 |
| 建议 | 在 `manifest.json` / `pages.json` 或 `main.ts` 设置 `uni.setLocale('zh-Hans')`（或显式用 `confirmText`/`cancelText` 传中文） |
| 备注 | 我校验的**弹窗正文文案本身是正确的**（含套餐名 + 「删除后不可恢复，历史订单不受影响」） |

### 🟡 D-2 接口失败时静默显示空态（既有体验问题，用例 H2）

| 项 | 内容 |
|----|------|
| 现象 | 停掉后端后打开页面 → 显示空态「暂无套餐」，**无任何错误提示**，用户会误以为"没有套餐" |
| 证据 | 停 dev API → `{empty:true, emptyText:"暂无套餐", toast:null}` |
| 代码 | `loadServices()` catch 分支对非 403 一律 `services.value = []` |
| 影响面 | 本页 + 其它同模式页面 |
| 建议 | 非 403 失败时给 `uni.showToast('加载失败')` 或提供「重试」按钮，与空态区分 |

### 🟢 D-3 A4 加载态未做强验证（测试自身局限）

快速接口下「加载中...」窗口过短，未捕获到瞬时态。仅确认了 `.loading-tip` 元素存在于模板中。
**改进**：下次可用 `network route --delay` 人为放慢接口再断言。

## 五、测试过程自身的教训（如实记录）

测试脚本最初有 3 个会导致**假通过**的缺陷，均已修正后才得到本报告结论：

1. **`agent-browser errors --clear` 不生效** → 错误计数按页累加（2,3,4…）→ 改用**增量**计数
2. **未先 `open` 建立 origin** → 所有 `location.hash` 落在 `about:blank` → **29 页全假通过** → 加了 `BLANK!` 判定
3. **输入框读取方式错**：`.field-input` 是 uni-app 自定义元素，`.value` 恒为 null → 改用 `.field-input input` / `native setter + input 事件`

> 结论：**报告里的每一条"通过"都是修正测量方式之后的结果**；未修正前的任何"全绿"都不可信。
